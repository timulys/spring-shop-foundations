# 완성한 구매 기능을 처음부터 끝까지 점검하기

정상 주문은 주문 한 건과 항목 두 종류를 저장하고 장바구니를 비웁니다. 가격이나 장바구니 버전이 바뀌면 409로 다시 확인을 요청하고, 상품 서비스가 응답하지 않으면 제한 시간 안에 503을 돌려줍니다. 실패한 요청은 새 주문을 남기거나 장바구니를 비우지 않아야 합니다. 상태 코드와 저장 결과를 함께 보는 이유입니다.

## 같은 입력으로 기준 결과 만들기

새 회원으로 로그인하고 `P001`을 1개씩 두 번, `P002`를 1개 담습니다. 장바구니에는 키보드 한 행의 수량이 2, 마우스 한 행의 수량이 1로 표시됩니다. 상품 금액은 75,000원, 할인은 5,000원, 배송비는 0원, 최종 금액은 70,000원입니다. 모의 주문 후 장바구니는 비고 주문 상세에는 당시 상품명·단가·수량이 남습니다.

현재 상품의 이름이나 가격이 달라져도 과거 주문은 저장한 항목을 조회합니다. 주문 취소는 상태를 `CANCELLED`로 바꾸고 원래 금액을 유지합니다. 같은 주문을 다시 취소하면 409입니다. 이 과정의 결제와 취소에는 실제 청구·환불이 없습니다.

## 화면에서 확인할 순서

1. 새 폴더에서 프로젝트를 실행하고 회원가입·로그인을 진행합니다. 비밀번호가 가입 응답이나 화면에 다시 표시되지 않는지 봅니다.
2. 키보드 수량에 0을 입력해 변경합니다. 오류 안내와 입력값이 남고 서버 수량은 유지되는지 확인합니다. 2로 고친 뒤 마우스 1개를 담습니다.
3. 주문 요약의 70,000원을 확인하고 주문합니다. 상세의 상품 두 종류와 빈 장바구니를 확인합니다.
4. 주문을 취소하고 새로고침합니다. 같은 주문 번호와 CANCELLED 상태, 원래 금액이 보이는지 확인합니다.
5. 새 장바구니를 준비하고 상품 앱을 중단합니다. 새 주문 실패 안내에는 요청 ID가 나오고 기존 주문 상세는 계속 열려야 합니다. 앱을 복구한 뒤 현재 장바구니를 다시 조회합니다.
6. 로그아웃·로그인을 거쳐 이전 주문을 다시 엽니다. 다른 회원으로 로그인하면 첫 회원의 주문은 보이지 않습니다.

상품 앱 중단과 복구는 다음 명령을 사용합니다. 중단 후 새 장바구니를 담으려고 하면 상품 조회 단계에서 실패하므로, 장애 전 장바구니와 주문 확인을 먼저 준비합니다.

```bash
docker compose stop catalog
docker compose up -d --wait catalog
```

같은 키 재전송은 [재시작 뒤 주문 복구](restart-replay.md)의 절차를 따릅니다. 응답 유실은 서버가 주문을 저장한 뒤 클라이언트가 응답을 받지 못한 상황입니다. 화면이 기다리기를 멈춘 시점만으로 주문 실패를 판단할 수 없으므로, 저장한 키와 확인 본문으로 결과를 다시 받습니다.

## 실패 결과에서 원인으로 돌아가기

금액이 다르면 상품 응답과 정책 계산을 비교합니다. 409이면 오류 코드로 가격 변경·장바구니 변경·키 재사용을 구분합니다. 503이면 화면의 요청 ID로 NGINX·주문 앱·상품 앱 로그를 이어 읽습니다. 상태는 맞는데 DB에 예상 밖의 행이 남으면 트랜잭션과 재시도 경계를 봅니다.

컨테이너를 다시 만들어도 볼륨은 유지됩니다. `docker compose down` 뒤 다시 실행하면 기존 데이터로 시작하고, `docker compose down -v`는 이 프로젝트의 데이터 볼륨을 삭제합니다. DB 갱신 실습은 별도의 Compose 프로젝트와 볼륨에서 진행해 기존 학습 데이터를 보존합니다. 주문 앱 재시작 뒤에는 메모리 세션이 사라지므로 다시 로그인합니다.
