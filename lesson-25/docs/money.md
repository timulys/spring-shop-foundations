# 원 단위 금액을 Money로 계산하기

Money는 0원 이상의 원 단위 금액입니다. `common.money`에 두고 장바구니와 주문에서 사용합니다. 금액이 같으면 같은 값으로 비교하며, 계산은 원래 객체를 바꾸지 않고 새 Money를 반환합니다. 레코드의 구성 요소가 기본형 long 하나이므로 내부에 변경 가능한 객체도 없습니다.

| 연산 | 결과·조건 |
|---|---|
| ofWon(30000) | 30,000원 값 생성 |
| plus | 두 금액의 합. long 범위를 넘으면 ArithmeticException |
| minus | 차액. 결과가 음수이면 IllegalArgumentException |
| times | 0 이상의 수량을 곱함. 음수 수량과 long 범위 초과를 거부 |
| isAtLeast | 기준 금액 이상인지 비교 |
| won | 저장·응답에 사용할 long 값 |

상품 가격은 Product에서 1~1,000,000원으로 제한합니다. 주문 수량은 OrderItem에서 1~99로 제한합니다. Money는 무료 배송과 할인 없음의 0원을 표현해야 하므로 0원을 허용합니다. 각 업무의 더 좁은 조건은 해당 객체가 검사합니다.

장바구니는 현재 상품 단가, 주문은 주문 항목에 저장한 당시 단가를 Money로 바꾸어 계산합니다. OrderItem.lineAmount가 항목 금액을, ShopOrder.confirm이 합계·할인·배송비·최종 금액을 계산합니다. JPA 필드와 응답 DTO는 long을 유지합니다. 따라서 테이블, JSON 필드와 프런트엔드의 금액 표시 형식은 같습니다.

Money가 처리하는 것은 금액의 값과 산술 규칙입니다. 50,000원 이상일 때 5,000원을 할인하고 배송비를 0원으로 정하는 상점 정책은 현재 ShopOrder에 있습니다. 정책을 별도 객체로 나누는 과정은 후속 강의에서 다룹니다.

확인 값: 49,999원 주문은 할인 0원 + 배송비 3,000원으로 최종 52,999원입니다. 50,000원 주문은 할인 5,000원 + 배송비 0원으로 최종 45,000원입니다. 키보드 2개와 마우스 1개는 합계 75,000원, 최종 70,000원입니다.
