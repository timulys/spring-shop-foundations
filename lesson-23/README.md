# 23강 · 로딩과 실패 뒤 화면 복구

응답 대기, 연결 실패, 잘못된 수량을 구분합니다. 실패해도 입력값을 남기고, 아직 적용하지 않은 수량이 있으면 주문 확인을 잠급니다. 연결을 복구한 뒤 정상 주문과 취소까지 이어서 확인합니다.

## 실행

JDK 21과 Docker가 필요합니다. Spring Boot 4.1.2, PostgreSQL 18.4, Gradle Wrapper 8.14.3을 사용합니다.

```bash
docker compose --profile test up -d --wait db test-db
./gradlew test
./gradlew bootRun
```

Windows에서는 `./gradlew` 대신 `gradlew.bat`를 사용합니다. http://127.0.0.1:8080/ 에서 시작합니다. IntelliJ에서 build.gradle을 열고 Project SDK와 Gradle JVM을 21로 지정합니다. 일반 DB 포트는 15432, 테스트 DB 포트는 15433입니다. 이전 강의의 앱과 컨테이너를 종료한 뒤 실행해 주세요.

공통 요청 함수의 테스트는 Node.js 22 환경에서 `npm run test:ui`로 실행합니다. 설치할 npm 패키지는 없습니다. 브라우저와 서버 실행에는 Node.js가 필요하지 않습니다.

## 주요 변경

- api.js: 기본 12초의 응답 대기 제한, HTTP 오류 보존, 미확인 응답 구분, 타이머 해제.
- cart.js: 실패 시 입력 요소 유지, 현재 입력 수량과 마지막 서버 수량 비교.
- checkout.js: 미적용 수량이 있으면 주문 확인 잠금, 수량 편집 시 기존 확인 무효화.
- HTML·CSS: 미적용 수량 안내.

12초는 이 실습에서 선택한 화면 복구 기준입니다. 브라우저의 대기 중단이 서버의 처리 취소나 롤백을 보장하지 않습니다. 생성·변경·취소 요청을 자동 반복하지 말고 조회로 현재 상태를 확인합니다.

## 브라우저에서 확인

1. 키보드 1개를 담습니다. 수량에 0을 넣고 변경하면 입력값이 남고 1~99 정수 안내가 표시됩니다. 서버 합계는 30000원입니다.
2. 수량을 2로 고칩니다. 개발자 도구의 Network에서 Offline을 선택하고 변경합니다. 실패 안내가 표시되고 입력한 2가 남습니다. 합계는 마지막 서버 조회 값이며 주문 확인 버튼은 잠깁니다.
3. Network를 3G로 바꾸고 장바구니를 새로고침합니다. 대기 중 버튼과 입력이 잠겼다가 응답 후 풀립니다. 실제 서버 수량인 1이 다시 표시됩니다.
4. No throttling으로 복구합니다. 수량 2를 적용하고 마우스 1개를 담으면 합계는 75000원입니다. 주문 확인에서는 할인 5000원, 배송비 0원, 최종 금액 70000원을 확인합니다.
5. 주문 확인 뒤 수량을 편집하면 이전 요약이 사라집니다. 입력을 적용하거나 장바구니를 다시 조회한 뒤 주문 내용을 새로 확인합니다.
6. 모의 주문을 완료하고 상세 조회·취소·새로고침을 차례로 실행합니다. 취소 상태와 상품 두 종류, 70000원이 유지되어야 합니다. 실제 청구나 환불은 없습니다.

오류 안내만 보지 말고 입력값, 합계, 버튼, 서버 조회 결과를 함께 비교해 주세요. DevTools의 제한 설정은 실습이 끝나면 No throttling으로 돌립니다. 현재 앱의 주문과 장바구니는 로그인 전 학습용 범위입니다.
