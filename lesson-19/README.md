# 19강 · 상품 목록과 상세 화면 완성하기

상품 API를 카테고리·상품명 검색과 상세 패널에 연결합니다. 18강의 공통 호출 함수를 그대로 사용하고, 서버가 돌려준 상품명·가격·카테고리를 표시합니다.

## 실행

JDK 21, Docker가 필요합니다. Spring Boot 4.1.2, PostgreSQL 18.4, Gradle Wrapper 8.14.3을 사용합니다.

```bash
docker compose --profile test up -d --wait db test-db
./gradlew test
./gradlew bootRun
```

http://127.0.0.1:8080/ 에서 시작합니다. IntelliJ에서는 이 폴더의 `build.gradle`을 열고 Project SDK와 Gradle JVM을 21로 선택한 뒤 `ShopApplication`을 실행합니다. 일반 DB 포트는 15432, 테스트 DB 포트는 15433입니다. 이전 강의 앱과 컨테이너를 종료한 뒤 실행해 주세요.

## 이번에 작성하는 코드

- `src/main/resources/static/product-query.js`: 카테고리·검색어를 요청 주소로 만듭니다.
- `src/main/resources/static/shop.js`: 검색 이벤트, 목록 표시, 상세 요청과 표시를 연결합니다.
- `index.html`과 `shop.css`는 검색 폼·카드·상세 패널의 제공 화면 틀입니다.
- `api.js`와 Java 서버, DB 구성 및 테스트는 앞 강의에서 이어받습니다.

## 확인할 결과

| 조작 | 결과 |
|---|---|
| 첫 화면·조건 초기화 | 키보드 30000원, 마우스 15000원, 노트 5000원 |
| 카테고리 주변기기 | P001·P002 두 상품 |
| 카테고리 문구 | P003 노트 한 상품 |
| 전체에서 상품명 키보드 검색 | P001 한 상품 |
| 문구에서 키보드 검색 | 200 응답의 빈 배열과 검색 결과 없음 안내 |
| P001 상세 보기 | API 상세 응답의 P001·키보드·주변기기·30000원 |

카테고리 변경은 현재 입력된 검색어와 함께 적용됩니다. 검색 버튼이나 엔터로 상품명 검색을 실행합니다. 조건 초기화는 카테고리와 검색어를 모두 비우고 전체 목록을 다시 요청합니다. 요청 중에는 입력과 버튼을 잠그고, 끝난 뒤 복구합니다.

Network에서 `/api/products?category=...&q=...`와 `/api/products/P001`의 응답을 비교해 주세요. 한글과 특수문자는 URLSearchParams가 인코딩합니다. 표시 금액은 API의 숫자에 천 단위 구분 기호만 붙인 값입니다.

## 과제

`loadProducts`에서 검색 결과가 0개일 때 안내 문구를 표시해 보세요. 문구 카테고리와 키보드 검색어를 함께 적용했을 때 카드가 사라지고, “검색 결과가 없습니다. 다른 조건으로 검색해 주세요.”가 나타나면 통과입니다. 조건 초기화 후 세 상품이 다시 나타나는지도 확인해 주세요. 이 폴더는 과제 정답을 포함한 완성 코드입니다.

서버가 보낸 글자는 `textContent`로 넣습니다. 상품명에 꺾쇠가 있어도 HTML로 해석하지 않습니다. 로그인·사용자별 장바구니·결제는 이 강의 범위에 포함되지 않습니다.

```bash
docker compose --profile test down
```

종료 명령은 일반 DB 볼륨을 보존합니다. 테스트 DB는 임시 저장소이며, 테스트 실행 전후에 테스트 데이터만 정리합니다.
