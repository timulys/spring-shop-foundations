# 22강 · 주문 내역과 취소 화면

주문 목록에서 상세를 열고 주문 당시의 상품·금액을 확인합니다. 주문을 취소하면 상태가 바뀌고 취소 버튼은 잠깁니다. 새로고침해도 취소 상태와 원래 금액이 유지됩니다. 실제 청구나 환불은 없는 학습용 예제입니다.

## 실행

JDK 21과 Docker가 필요합니다. Spring Boot 4.1.2, PostgreSQL 18.4, Gradle Wrapper 8.14.3을 사용합니다.

```bash
docker compose --profile test up -d --wait db test-db
./gradlew test
./gradlew bootRun
```

Windows에서는 `./gradlew` 대신 `gradlew.bat`를 사용합니다. http://127.0.0.1:8080/ 에서 시작합니다. IntelliJ에서 이 폴더의 build.gradle을 열고 Project SDK와 Gradle JVM을 21로 지정한 뒤 ShopApplication을 실행합니다. 일반 DB 포트는 15432, 테스트 DB 포트는 15433입니다. 이전 강의 앱과 컨테이너를 종료한 뒤 실행해 주세요.

## 작성할 코드

- `src/main/resources/static/orders.js`: 주문 목록·상세 조회, 상태 표시, 취소, 페이지 이동.
- `shop.js`: 주문 내역의 첫 조회.
- `checkout.js`: 주문 완료 뒤 `shop:order-created` 알림.
- HTML·CSS와 서버의 주문 조회·취소 API는 제공 파일입니다.

## 확인할 결과

1. 키보드 2개와 마우스 1개로 주문하면 70000원이 저장되고 주문 목록이 자동 갱신됩니다.
2. 노트 1개로 주문을 하나 더 만듭니다. 상품 합계 5000원에 배송비 3000원이 더해져 주문 금액은 8000원입니다. 최근 주문이 위에 표시됩니다.
3. 첫 주문의 상세를 엽니다. 상품 두 종류와 상품 합계 75000원, 할인 5000원, 배송비 0원, 주문 금액 70000원이 보입니다.
4. 취소를 누르면 `CANCELLED`를 ‘취소 완료’로 표시하고 취소 버튼을 잠급니다. 주문 항목과 금액은 남고 장바구니는 비어 있습니다.
5. 브라우저를 새로고침하고 같은 주문의 상세를 다시 엽니다. 취소 상태와 금액이 유지되는지 확인합니다.
6. 주문이 6건이면 첫 페이지에 5건, 다음 페이지에 1건이 보입니다. 첫 페이지는 이전 버튼, 마지막 페이지는 다음 버튼이 잠깁니다.

목록은 `GET /api/orders?page=0&size=5`, 상세는 `GET /api/orders/{id}`, 취소는 `POST /api/orders/{id}/cancel`을 호출합니다. API의 페이지 번호는 0부터, 화면 표시는 1부터 시작합니다. 목록 조회가 실패하면 이전 결과라는 안내를 붙이고 기존 목록을 유지합니다. 취소 응답을 받지 못하면 요청을 자동 반복하지 않고 내역과 상세를 다시 조회합니다.

`OrderQueryTest`, `OrderPaginationTest`, `OrderCancellationTest`에서 저장 당시 값, 정렬·페이지 경계, 취소와 재취소 거부를 확인할 수 있습니다. 테스트는 `shop_test` 전용 DB를 사용합니다. 현재 장바구니는 학습용 사용자 1번으로 고정되어 있으며 사용자 구분은 이후 강의에서 확장합니다.
