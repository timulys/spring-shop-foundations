# 39강 주문 데이터를 유지하며 전환하기

39강과 40강은 같은 `order_data`·`catalog_data` 볼륨 이름을 사용합니다. Compose 프로젝트 이름도 같게 지정하면 기존 볼륨을 재사용할 수 있습니다. 40강의 주문 앱은 V8을 적용해 자기 DB의 `products` 테이블을 제거합니다. 회원·장바구니·주문·주문 항목과 기존 마이그레이션 이력은 유지합니다.

이 실습의 상품 DB에는 39강에서 만든 초기 상품이 이미 들어 있습니다. V8은 주문 DB의 이전 상품 테이블을 삭제하는 단계이며, 그 테이블의 변경 데이터를 상품 DB로 복사하지 않습니다. 실제 운영 데이터를 전환할 때는 상품 데이터 이전·변경 동기화·복구 절차를 먼저 준비해야 합니다.

전체 코드 ZIP에서 `lesson-39`와 `lesson-40`을 각각 사용합니다. 두 폴더에서 `.env.example`을 `.env`로 복사하고 같은 두 DB 비밀번호를 사용합니다. 먼저 `lesson-39`에서 실행합니다.

```bash
docker compose -p shop-http-upgrade up -d --build --wait
```

가입·로그인 후 주문을 만들고 번호·항목·금액을 기록합니다. 같은 폴더에서 `docker compose -p shop-http-upgrade down`으로 종료합니다. `-v`를 추가하면 데이터 볼륨도 삭제되므로, 이번 데이터 유지 실습에서는 사용하지 않습니다.

이제 `lesson-40` 폴더에서 실행합니다.

```bash
docker compose -p shop-http-upgrade up -d --build --wait
```

앱 메모리 세션은 새 앱 실행으로 사라졌으므로 다시 로그인합니다. 이전 주문이 그대로 나오고 새 주문도 70,000원으로 생성되는지 확인합니다. 주문 DB의 `products`는 없어지고, 상품 DB의 세 상품은 남아 있어야 합니다.

이전 버전으로 되돌리려면 제거한 테이블과 데이터의 복구 계획이 필요합니다. 이 실습의 V8에는 자동 역방향 마이그레이션이 없습니다. 강의를 독립적으로 처음 실행하려면 기본 프로젝트 이름을 사용하면 됩니다. `spring-shop-lesson39`와 `spring-shop-lesson40`의 볼륨은 서로 구분됩니다.
